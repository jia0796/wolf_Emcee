### 一、不可更動的最新主持與玩家流程

**主持人流程（必須以此為準）**

開始主持 → 選擇「傳統主持」或「線上發牌」 → 選線上發牌後自動建立並顯示房間 → 房間顯示大型 QR Code、房號、複製連結、10／12 人環形座位與入座狀態 → 全員入座 → 點擊一次「開始發牌」 → 伺服器確認完成後**直接進入原本正常主持頁面** → 此後全部按照傳統主持原流程操作。

- 選擇「傳統主持」不變更任何既有功能。「線上發牌」只能在開始主持前選擇，不允許在已進入傳統主持流程後臨時啟用。
- 自動建房須防重複；不可因網路重試或刷新而產生第二間房。主持端房間的 QR Code **固定大型**、位於座位資訊上方，不需放大按鈕。房號及「複製連結」可直接分享同一邀請網址。
- 主持房間使用環形座位，座號 1 在最上、其餘順時針，依原板子為 10 或 12 人。座位中央**完全不放文字、數字或圖示**；可保留未來背景圖空間，不預先決定背景素材。環形區淡冰晶半透明，其他美術及人數資訊外部排版交由 Codex。
- 底部固定「開始發牌」：未滿員時**暗沉但仍可點**，按下必須顯示原文**「遊玩人數不足，無法發牌」**；滿員後按鈕亮起。滿員**不自動發牌**，主持人主動按一下，且**不跳確認**。
- 按下後按鈕顯示「發牌中…」，防止重複提交；原子性檢查／鎖定席位，使用已確認的同一套板子角色分配。結果不明或失敗時**留在房間**，安全查證原交易後才可重試，不能重洗牌。
- **發牌成功立即進入既有主持頁面**，不等玩家翻牌、不記錄是否查看、不增加查看確認、進度或主持端返回發牌房間的功能。線上發牌後端保留原玩家角色卡讀取權，直到**原主持流程正式終局，或主持人明確確認結束／解散本局**；切背景、刷新與短暫斷線不算結束。
- 發牌前，主持可點已占座號並**再次確認**後釋放座位；也可用房間右上角**小型解散房間**入口，二次確認成功後直接返回 WolfCue 首頁。發牌後座位鎖定，原主持頁面不額外增加解散按鈕；使用原「重新開局 → 回首頁」確認後，先刪除線上房間，成功才清本機對局。網路失敗或回應不明時保留本局供重試。

**玩家流程（必須以此為準）**

掃 QR／開連結 → 顯示板子 10／12 人環形選座 → 點選空座號直接入座 → 等待時保持環形畫面 → 主持人發牌時顯示「正在發牌…」 → 伺服器確認完成自動出現**一張卡背** → 點卡翻牌顯示本人角色 → 可反覆蓋牌／翻牌並停留角色卡頁面 → 可看本板子圖鑑或二次確認返回首頁 → 正式終局自動蓋牌、返回首頁並失去角色卡存取權。

- 玩家匿名加入，不輸入暱稱，只有座號。入座後等待區下方顯示「離開座位」；離座需二次確認。發牌前可點其他空位**一鍵換座**，不必先離座；換座失敗必須保留原座，且短暫斷線不可自動釋放座位。主持清除時玩家立即返回選座頁並顯示簡短提示；原占位憑證失效。
- 多人同搶一座由伺服器決定唯一成功者，落敗者看到**「X 號已被其他玩家選擇，請選擇其他座位」**，更新座位畫面；沒有位置時顯示**「房間人數已滿，無法加入」**。已完成發牌後，新訪客也使用這句滿員提示並可返回首頁；不額外透露房間是否發牌。
- 卡背顯示 WolfCue／狼序圖案、「X 號玩家」及「點擊翻牌」，不透露角色與陣營。整張卡背、整張卡正面均可點擊，3D 翻轉約 0.35 秒；翻轉動畫中額外點擊被忽略。卡正面**只顯示原核准角色插畫、按陣營顏色顯示的職業名稱**；**不顯示技能文字**。
- 「本板子圖鑑」位於玩家介面右上角，**未入座、等待、卡背及卡正面都能進入**。只顯示本板子角色的既有圖文介紹／技能，不透露座位分配。每次開啟從圖鑑首頁開始；已翻開卡時開圖鑑會**立即蓋牌**，返回卡頁仍為卡背。玩家在圖鑑中遇到發牌成功亦直接顯示卡背。
- 角色卡頁面上方固定座號與本板子圖鑑，下方固定「回首頁」，中間角色卡等比例自適應、短螢幕可捲動；點「回首頁」須二次確認。回首頁後僅可在**原瀏覽器／原房間有效憑證**條件下再使用原 QR／連結重進；**首頁不新增「角色卡」捷徑**，不提供換手機、換瀏覽器或主持核准轉移憑證。
- 切 App、鎖螢幕／頁面隱藏、開圖鑑、重整或需重新驗證權限時，**蓋牌隱私事件優先於翻牌動畫，立即遮蔽角色**。原瀏覽器有效憑證重新整理／斷線恢復可自動同步並恢復同一角色卡，但**預設卡背**。即使主持已進入夜晚／白天，玩家仍停留自己的卡頁，不需跟著切主持階段。
- 主持人解散房間：伺服器同交易刪除房間、授權、座位、邀請、發牌及角色資料；所有玩家立即蓋牌並回首頁，圖鑑與多分頁也退出。離線玩家於恢復連線查證後退出。未發牌閒置 2 小時、已發牌不依閒置關閉的既有規則不變；已發牌可因正式終局或主持人明確確認結束而刪除，不自行產生勝負。

### 三、Supabase 安全後端開發規格（本章仍為待實作）

**既有人工前置設定（使用者已完成並回報）**：已建立 Supabase 專案並取得 Project URL／Publishable key；已啟用 Anonymous Sign-Ins；已將 Realtime「Allow public access to channels」設為 Disabled。**這不代表已建立 SQL Migration、RLS、Realtime 私有授權或 Edge Functions。**

- **部署方式**：保留 GitHub Pages 前端，使用 Supabase Auth Anonymous JWT、PostgreSQL／RLS、Private Broadcast Channels 與受授權 Edge Functions；不得將 service_role／secret key、DB 密碼或角色總表放在 GitHub Pages。
- **資料模型草稿**：rooms（建立、板子、容量、主持者、狀態、最後有效活動）、room_access（房間成員及憑證撤銷）、room_seats（座號與持有人）、deal_transactions（單次發牌交易／冪等性）、player_roles（隱藏角色）；實際 SQL 欄位須先檢查原專案結構、板子配置與安全需求，不任意假設可新增角色／板子。
- **權限要求**：每次操作驗證 Auth JWT 及所屬房間角色；玩家不得查別人角色或任意取整房角色表，非主持人不得清除玩家或開始發牌，未入房者不得讀取房內敏感資料。所有暴露資料表要檢查 GRANT／REVOKE 與 RLS，不可僅依賴前端隱藏 UI。提升權限的 SQL 函式需最小授權、受限執行權及安全 search_path。
- **Realtime 要求**：全部使用私有頻道（private: true），以 realtime.messages 的 RLS 驗證可訂閱者與事件發送者。只廣播非機密的座位／房間變更或版本訊號；**絕不廣播職業、全房身分表、使用者憑證、密鑰或看牌狀態**。新分頁、重整及斷線重連都必須向伺服器抓取最新授權快照，不依賴單靠廣播結果。
- **交易與冪等性**：選座、換座、清除及發牌須原子處理並設 DB 唯一約束；同座不可雙占、同房同人不可雙席。原子換座失敗不得釋出舊座；發牌須滿員、鎖席、同一交易不可重洗，結果不明只能查原交易。建立房間也須用穩定冪等請求識別，避免多分頁或網路重試建立兩房。
- **角色來源**：以原有角色組成／抽牌規格為準，伺服器安全完成並保存唯一角色配置；客戶端僅可取自己角色，不能指定欲領取角色。整合既有主持資料必須經最小介面契約，不得篡改原 engine.js 的主持流程／存檔或復盤。
- **終局與時效**：尚未發牌且無有效操作 2 小時由後端關閉；不把心跳、無意義輪詢當作有效操作。既有遊戲「正式終局」或主持人明確確認結束本局時刪除房間及角色資料；主持切 App、刷新或短暫斷線不能等同終局。
- **重整與多分頁**：同一原瀏覽器的合法玩家可恢復本人席位／角色，多分頁同時訂閱並操作線上發牌時以伺服器事務及版本判定衝突。**禁止將新多分頁政策套到傳統主持頁的本機存檔／回退邏輯**；不同裝置／不同瀏覽器不轉移玩家憑證。
- **客戶端隱私**：背景隱藏、圖鑑切換、刷新、權限未知、房間解散、逾時或終局時避免角色正面持續展示；不在快取／日誌／Realtime 推送全體身分，不建立「已查看角色」的紀錄、統計或 UI。

**階段 2：獨立後端草稿及本機安全測試**：在原 Git 工作樹之外建立本機獨立工作目錄，產生 SQL Migration、完整 RLS 與授權、private Realtime、Edge Functions 和虛構測試資料；沒有完整工具環境就如實回報未測。此階段**不得修改原 App、GitHub／Google Drive、遠端 Supabase 資料庫、雲端 Auth／Realtime 設定，也不得部署**。

**階段 3：驗收**：至少覆蓋 10／12 人容量、同座競爭、換座失敗保留、離座／清席及憑證撤銷、滿員拒加入、不足人數點按提示、主持／玩家多分頁重送、發牌同時換座／離座、原子發牌與重試冪等、斷線／重新整理／建房結果不明、私有 Realtime 阻止未授權訂閱與偽造通知、跨房／越權讀牌、開圖鑑蓋牌、背景立即蓋牌、解散／2 小時閒置／正式終局撤權、原主持遊戲與舊存檔回歸。需列出實際通過、失敗、未執行與待驗收；**iPhone Safari／iOS PWA／Android／低階裝置真機未跑不得宣稱通過**。

**階段 4：使用者明確確認後，才可整合或部署**。先提交架構檢查報告、Migration／RLS 草稿、Realtime 與 Edge Functions 草稿、安全與回歸測試、最小 App 整合計畫及金鑰設定清單。不得自行 push 其他檔案、改現有 App、部署 Supabase、變更遊戲機制、強制推送、重置或刪除既有 Git 回退歷史。**本次文件寫入只代表規格入庫，不代表已開始後端部署。**
