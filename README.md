**適用邊界**：只修改**已存在「多人投同一位」操作模式**的可選區／已記錄區顯示行為。依 **HOST-03-01／方案 A**，適用一般放逐、警長選舉、警長 PK／重投及放逐 PK／重投；各投票類型**原有對話框樣式、流程、投票資格、合法得票對象、警徽加權**維持原狀。這不是把 VOTE-01～62 的新版一般放逐編輯器整套移植到警長／PK。

| 編號 | 定案規格與施工界線 |
|---|---|
| **03-01／方案 A** | 在同一投票輪次，已記錄投給其他得票對象的投票者，**不再出現在目前得票對象的可選區**。仍保留可查詢／取消的票型紀錄，取消後恢復可選；進入新一輪或 PK 輪次時依**原本該輪投票資格**重新計算，不複製前輪票權／票型。 |

| **03-04／方案 A** | 隱藏其他得票對象已投票者後，剩下的合法玩家依原座號**緊湊補位、不留空格**；取消後按原座號恢復。僅改可選名單的 UI 排列，不變更票權及選票資料。 |

| **03-07／方案 B** | 各得票對象群組依**實際加權得票數由多至少**排序；同票依**該輪原得票對象順序**（現有合法對象按座號排列）作穩定次序；組內投票者維持原座號序。**既有 `tallyVotes` 和 `voteGroups` 已提供同等分組／排序，應沿用而非重做**。 |

**已存在、不列為新開發的行為**：

- `public/vote-ui.js` 的多人模式本來就可對**目前得票對象**點一次投票、再次點擊取消；本次只調整其他得票對象的已投票者可見性和全員完成後的呈現。
- `public/votes.js` 的 `setBallot`、`tallyVotes`、`voteGroups` 和正式 `voteResultCard` 已負責變更選票、加權得票／分組排序、現有結果與復盤；**不得為 HOST-03 另造獨立票數狀態或另一套 PK 判定**。
- 原紀錄入口（「紀錄票型」／「紀錄票型（選用）」）、兩模式共用資料、一般放逐得票對象條列清單、逐人「上一位／下一位」與未選下一位棄票、完成統計、關閉及同輪續編／重新編輯、放棄票型、原有結果顯示／復盤資格均沿用。
- **草稿與正式提交嚴格區隔**：HOST-03 畫面中的「已記錄」是本次編輯草稿已填的票型，**不是指已按「完成統計」的正式提交**。點選／取消只更新草稿與其即時顯示；**完成統計**才透過原提交路徑更新正式票型、原結果預選／鎖定及復盤資格。關閉未提交的更動不能直接毀損上一次正式提交的紀錄；不同投票輪次與 PK 也不可混入前輪草稿。
- 已有**全員未投／棄票**、候選人零票、合法投票人數進度及加權票數各自的既有定義；**不能將有效選票 X/Y 簡單等同「所有人已完成紀錄」**，不得為觸發收起可選區而擅自將未記錄者視為投票完成。原完成統計時自動棄票、全員棄票結果、PK 投票權、警長 1.5 票及舊局歷史均維持。

### 2. 啟動、重整及恢復判定矩陣

| 使用情境 | 是否播放 |
|---|---|
| 從桌面圖示全新啟動已安裝 PWA，並進入首頁 | **播放一次** |
| 瀏覽器全新分頁直接進入 WolfCue 首頁 | **每個新分頁播放一次** |
| 既有分頁手動重新整理、下拉刷新、一般重載 | **不播放** |
| 切到其他 App／分頁後回來、PWA 從背景或休眠恢復、瀏覽器回復原分頁 | **不播放** |
| 由 WolfCue 內部任一功能頁返回首頁 | **不播放** |
| 偵測到應直接恢復既有主持對局 | **不播放，直接恢復主持操作** |
| QR Code／線上邀請連結直接進入線上房間（非首頁） | **不播放** |
| 使用者系統設定「減少動態效果」（prefers-reduced-motion: reduce） | **直接呈現目的頁，不播開場** |

**啟動判定實作注意**：
- 不能只因 JavaScript 重新執行就判定為全新開啟，否則重新整理會誤播。必須辨識頁面導航類型、恢復事件及每個分頁生命週期，且考慮 BFCache、頁面複製可能繼承 sessionStorage、PWA 被系統保留或重新載入等情境。
- 不得以全域單一「已播放」旗標阻止其他真正的新分頁播放；也不得因跨分頁共用存檔而錯誤觸發動畫。啟動判定不應修改或遷移遊戲的存檔資料。
- iPhone 已安裝 PWA 的**作業系統原生靜態啟動畫面**不是 Web 動畫的一部分；本規格僅要求網頁載入後的 WolfCue 視覺開場。系統是否從冷啟動或背景恢復，有時無法精確辨識，不可宣稱各種 iOS 情況都能 100% 判定。

### 1. 共通規則

- **基本接刀資格只在每晚開始時計算**：前一白天最後原始狼人出局，下一晚才能接刀；當晚夜間中途全滅不追補狼刀。機械狼、假面、尋香魅影於本板所有原普通狼人出局且自身存活時接刀。**轉化者**須原普通狼人及覺醒石像鬼全部出局，且已成功轉化、本人存活、符合原 joinNight 加入時機，才接刀；轉化者自己不列入原始狼人存活數。**轉化必定成功，不存在「轉化失敗」狀態。**
- 四種角色的基本狼刀與機械狼學狼人取得的額外狼刀**均可自刀、可空刀**；可以跟原本技能同晚使用，也可指定相同座號；保留各自技能限制。機械狼兩把刀可同晚各刀一次，同人亦可，兩次獨立傷害／使用紀錄。
- **角色「請閉眼」畫面按下一步，才正式提交**狼刀與技能結果；此前可自由選擇、取消、修改。閉眼主字幕不變，僅有狼刀資格時顯示小字目標或空刀摘要（機械狼基本／額外分開）。空刀可直接下一步，不建假攻擊。
- **所有原普通狼人出局後，原狼人階段仍完整保留「狼人請睜眼」→「選擇你們今晚要襲擊的對象」→「狼人請閉眼」**，座位環照常顯示但不能選刀，也不能改空刀或覆蓋已提交刀口；接刀特殊角色在此不再操作，不重複產生狼刀紀錄。真正終局仍立即停止後續字幕。同時仍有原普通狼人時原狼人選刀流程不變。不得因轉化者被統計為狼人而使原狼人階段重複操作。
