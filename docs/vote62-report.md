### 復盤資格的具體結果

| 下一步當下狀態 | 復盤 | 原始票型 |
|---|---|---|
| 只有草稿，主持人手動放逐 | 不顯示 | 草稿仍在原輪次資料／回退快照 |
| 已統計，最終手動改選其他玩家 | 不顯示該輪票型 | 正式選票保留，僅 confirmed=false |
| 下一步前改回最新正式統計預選 | 正常顯示 | confirmed=true，事件保存原票型快照 |
| 修改並重新統計 | 以新預選結果重新判定 | 再提交前原正式資料不變 |
| 同票後進入放逐 PK | 沿用原 PK 階段，兩輪獨立 | 確認合格的輪次各自保留 |

**全員棄票沒有新增遊戲規則：**統計只保存票型，不提供零票候選人，也不自動放逐或進 PK。原手動選擇／同票控制及下一步條件維持。若最終手動選擇與統計預選不符，依同一規格不顯示該輪復盤票型，但原始棄票資料保留。

### 首輪失敗與處理

- 基準分支 worker 已是 `council-v22-3`，三處原測試仍硬編碼 v22-2，造成既有快取測試失敗；在獨立測試提交修正，**沒有修改 sw.js 或快取策略**。
- 三處普通放逐舊測試仍要求鎖定手動改選／拒收全棄票，與本次定稿相反。更新成明確的新規格斷言，並另外驗證三種舊編輯器仍維持舊限制。
- 補測時修正兩個測試 fixture：JSON 不保存 undefined 欄位、警長選舉原票型不帶放逐警長權重。未更動 App 行為去遷就錯誤 fixture；最終所有測試重跑通過。

## 7. 尚未驗收、限制與可優化項目

本輪已執行案例中無尚未修復的阻斷 Bug；這不代表所有裝置與所有操作組合都已窮盡。

1. **未驗收：實體 iPhone Safari、iOS 安裝版 PWA、Android、低階裝置。** 特別需實測動態網址列、Home Indicator／瀏海、觸控慣性捲動／誤觸、系統大字級、雙指縮放、背景切換與裝置儲存配額。桌面 viewport、pagehide 模擬與離線測試不能替代真機。
2. 極短橫向＋200% 字級時，標題候選區需內部捲動才能看到全部候選人。自動化已確認控制可達與提交可見；實際 iOS 巢狀捲動舒適度仍待體驗驗收，不為塞版面縮小觸控格。
3. 原有整局快照在長局持續累積，壓力中最大約 3.24MB；低配額環境仍有儲存上限風險。已驗證失敗回滾，**未為效能刪除歷史或改變存檔規則**。
4. 長局復盤及低階裝置的幀率／觸控延遲尚無真機量測；如日後優化，應保留票型資料與快照，只處理純顯示效能。
5. 全員棄票後的遊戲裁決未擴充；仍由原手動／同票流程處理。若要新增裁決，必須另行定稿，不能當成 UI Bug 自動補規則。

以上為待真機驗收／後續討論項目，本輪沒有順手擴大修改。
